# Schema-First Refactoring Plan

## Goal
Make the LinkML schema the ground truth. Pydantic classes become explicit wrappers that add convenience/validation on top of generated schema bases.

## Separation of Concerns

### Layer 1: Generated Schema (Ground Truth)
- Files: `laura/models/_generated.py` (auto-generated from YAML)
- Content: Pure Pydantic models from LinkML schema
- Ownership: Regenerated by `generate_pydantic.py`
- Modification: NO direct edits (changes in schema YAML only)

### Layer 2: Schema Wrappers (Type Refinement)
- Files: `element.py`, `physical.py`, `magnetic.py`
- Purpose: Override field types, add essential validators, add essential computed fields
- Scope: Minimal — only what's needed for Python API surface

### Layer 3: Utilities (Optional Convenience)
- New files: `element_utils.py`, `physical_utils.py`, `magnetic_utils.py`
- Purpose: Vector math, string parsing, conversions, debugging
- Scope: Optional — can be removed without breaking schema contract

## Implementation Strategy

### Phase 1: Create Utilities (Non-Breaking)
1. Create `laura/utils/` package
2. Extract vector math, conversions, matrix calculations
3. Update model classes to import from utils
4. **Impact: NONE** — existing API unchanged

### Phase 2: Simplify Schema Wrappers (Breaking)
1. Remove non-essential logic from model classes
2. Create explicit Layer 2 vs Layer 3 separation
3. Update documentation
4. **Impact: BREAKING** — some internal methods may disappear
5. **Mitigation:** Deprecation warnings, migration guide

### Phase 3: Make Cascading Optional (Breaking)
1. Move cascading access to optional mixin
2. Decide: keep as default or require explicit access?
3. Update tests
4. **Impact: HIGH** — cascading is widely used

---

## Backwards Compatibility Strategy

### Keep (Stable API):
- All public element types (Quadrupole, Dipole, etc.)
- All public fields (name, hardware_type, physical, magnetic)
- Serialization formats
- K/current conversions (move to utils, keep convenience wrappers)

### Change (Breaking):
- Internal methods (__getattr__ details, path-finding)
- Optional utilities (vector math, geometry helpers)
- Constructor variants (from_list, from_values)

### Deprecate (Graceful):
- Cascading attribute access (if removing)
- Direct calls to internal methods
